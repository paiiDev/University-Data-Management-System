# University Data Management System (Learning Management System)

A desktop application built with **C# Windows Forms** that helps a university manage its
**students**, **teachers (instructors)**, and **courses**. It has a login screen, and depending
on who logs in (Admin, Instructor, or Student) they see a different dashboard.

This README is written for **beginners**. Every step is explained in plain language, so you can
get the project running even if this is your first time using Visual Studio or a database.

## What this project does

Think of it as a simple school office app. With it you can:

- **Log in** as an Admin, an Instructor, or a Student.
- **Admin** can:
  - See at a glance how many students, teachers, and courses exist (the little counters).
  - Add new students.
  - Add new teachers.
  - Add, edit, and delete courses.
  - Update and delete students and teachers.
- **Instructor** can change their password when they log in for the first time.
- **Student** gets a dashboard (currently a starting point for future features).

All the data is saved in a **SQL Server database file** called `LMSDB.mdf`.

## The three types of users

| Role | What they can do |
|------|------------------|
| **Admin** | Full control: manage students, teachers, and courses |
| **Instructor** | Log in and change password (dashboard is a placeholder) |
| **Student** | Log in and see their dashboard (placeholder for now) |

The application decides which dashboard to open based on the email and password you type in on
the login screen. See `LearningMannagementSystem/LoginForm.cs`.

## Technologies used

- **Language:** C# (pronounced "C sharp")
- **Framework:** .NET Framework 4.5
- **UI type:** Windows Forms (WinForms) — the classic drag-and-drop desktop UI
- **Database:** Microsoft SQL Server LocalDB (a lightweight, file-based version of SQL Server)
- **Database access:** A mix of
  - **Entity Framework 6** (an ORM that lets you work with database tables as C# classes), and
  - **ADO.NET** (`SqlConnection`, `SqlCommand`) for hand-written SQL queries.

> **New word — ORM:** ORM stands for *Object-Relational Mapping*. It lets you treat a database
> table (like `students`) as a C# class (like `student`) so you can write C# instead of SQL.

## How to run the project

### What you need first

1. **Windows** (this app only runs on Windows).
2. **Visual Studio 2013 or newer** (the free *Community* edition is fine).
   - During installation, make sure you tick **".NET desktop development"** (or the
     **".NET Framework desktop"** workload) so WinForms is available.
3. **SQL Server LocalDB** — usually installed automatically together with Visual Studio.

### Steps

1. Download or clone this repository.
2. Double-click **`LearningMannagementSystem.sln`** to open it in Visual Studio.
3. Wait for Visual Studio to restore the **NuGet packages** (the Entity Framework library).
   - If you see a yellow warning bar at the top, click **Restore** / **Reload**.
4. Press the green **Start** button (or press **F5**) to build and run the app.
5. The **Login** window appears. Log in using the credentials below.

That's it — the database file is copied to the build folder automatically (see the
`CopyToOutputDirectory` setting in the `.csproj`), so no manual database setup is required.

## Default login details

The app ships with sample accounts. Passwords are **case-sensitive**.

| Role | Email | Password |
|------|-------|----------|
| Admin | *(whatever admin email is stored in the DB)* | the plain password stored in the `admin` table |
| Instructor | *(any instructor email in the DB)* | `instruct0r` (temporary password) |
| Student | *(any student email in the DB)* | `stud@nt` |

> **Heads up:** when an Admin adds a new student, that student always starts with the password
> `stud@nt`. New instructors always start with `instruct0r` and are forced to change it on first
> login (the `IsTempPassword` flag). You can see this in `Add_new_students.cs` and
> `Add_new_teachers.cs`.

> The `admin` table stores its password as **plain text**, while students and instructors are
> **hashed** with SHA-256 (see `PasswordHelper.cs`). That inconsistency is a good candidate for a
> future cleanup.

## How the code works

A quick tour of the most important files so you can find your way around:

- **`Program.cs`** — the entry point. `Application.Run(new LoginForm())` opens the login window.
- **`LoginForm.cs`** — reads the email and password boxes, then checks them against the
  `admin`, `students`, and `instructor` tables. Whichever matches decides which dashboard opens.
- **`PasswordHelper.cs`** — converts a plain password into a SHA-256 hash. Hashing turns
  `"stud@nt"` into a long scrambled string, so the real password is not stored in the database.
- **`Admin_Dashboard.cs`** — shows the counters (number of students/teachers/courses) and has the
  buttons that open the "Manage" and "Add" forms.
- **`Manage_*.cs`** — list records in a table (a `DataGridView`) and let you update or delete them.
- **`Model1.*` / `Admin.cs` / `Instructor.cs` / `student.cs` / `Cours.cs`** — the Entity Framework
  model. Each class is a table, and each property is a column.
- **`App.config`** — holds the database connection string named `LMSDBEntities`.

### The database tables

| Table | Columns (simplified) |
|-------|----------------------|
| `admin` | id, email, password (plain text) |
| `students` | studentID, Name, Email, Password (hashed), DOB, Phno, Address, LastModified |
| `instructor` | id, name, email, password (hashed), role, IsTempPassword, Education, Department, Phno, Address, dob, LastModified |
| `courses` | course_id, course_name, course_code, semester, credits, instructor_id (links to `instructor.id`) |

`courses.instructor_id` is a **foreign key** pointing to `instructor.id`, which is why a course
must belong to an instructor. The `SQLQuery1.sql` file shows the `CREATE TABLE` statement for
`courses`.

## Common problems and fixes

**1. "Cannot attach the database file ... LMSDB.mdf"**
The connection strings inside the code point to a hard-coded path like
`C:\Users\PAII\Documents\LMSDB.mdf`, which is the original author's computer. On your machine
this path likely does not exist.

- Quick fix: copy `LMSDB.mdf` (and `LMSDB_log.ldf`) to `C:\Users\<YourName>\Documents\`.
- Better fix: change the connection strings to use `|DataDirectory|` or your own path. Search
  the code for `AttachDbFilename` and update each form's `SqlConnection`. The `App.config`
  connection string already uses `|DataDirectory|\LMSDB.mdf`.

**2. Login always says "Email and Password are incorrect"**
- Make sure you are using a real email that exists in the database.
- Remember student/instructor passwords are **hashed** in the database, but the login form hashes
  what you type before comparing — so type the *plain* password (`stud@nt` / `instruct0r`).
- Passwords are case-sensitive.

**3. Build errors about Entity Framework**
Right-click the solution in the **Solution Explorer** and choose **Restore NuGet Packages**.

**4. LocalDB not installed**
Open *Visual Studio Installer* and add the **"SQL Server Express LocalDB"** individual component.

**5. "There is already an open DataReader"**
This can appear because some forms run several queries on one connection. Close and reopen the
form, or refactor to use separate connections (see improvement ideas below).

## Ideas for improvement

If you are learning from this project, these are great next exercises:

- **Hash the admin password too** — it is currently stored in plain text.
- **Stop hard-coding the database path** — move all connection strings into `App.config` and read
  them with `ConfigurationManager`.
- **Store one shared connection string** instead of repeating it in every form.
- **Use `using` blocks for connections** so they close automatically, even on errors.
- **Finish the dashboards** for Instructor and Student — they are empty placeholders.
- **Add real validation** (e.g. a proper email/phone check) instead of just looking for `@`.
- **Use Entity Framework everywhere** instead of mixing it with raw SQL for consistency.
